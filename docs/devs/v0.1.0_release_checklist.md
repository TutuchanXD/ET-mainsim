# ET-mainsim v0.1.0 release checklist

This checklist publishes the first ET-mainsim application baseline. It builds
package artifacts only. No scientific simulation, data asset, CUDA, H100, or
campaign output is part of this release procedure.

## Before the tag

- Confirm `git rev-parse HEAD` is the reviewed merge commit on `main`.
- Confirm `git diff --quiet` and `git diff --cached --quiet` both succeed.
- Confirm the required checks are green on that exact commit:
  `package-boundary / py3.12`, `package-boundary / py3.13`, and
  `full-test-gate`.
- Confirm `pyproject.toml`, `et_mainsim.__version__`, `et-mainsim --version`,
  and `ci/release_contract.toml` all identify `0.1.0` / `v0.1.0`.
- Install ET-coordinate commit
  `f9cec8038b021c9540a026b94e876dc3240071d1` (0.1.2) and Photsim7 commit
  `250b6bcbd3a79e3bb775a2e0cdf584b3f552185c` (0.2.5), install the candidate
  ET-mainsim wheel with `--no-deps`, and require `python -m pip check` to pass.

## Build the release candidate

Run the local package-only builder before tagging:

```bash
conda run -n etbase python -m ci.build_release --output /tmp/et-mainsim-v0.1.0
```

The command must produce two byte-identical independent builds and validate
the exact wheel and sdist member inventories. Retain these generated files:

- `et_mainsim-0.1.0-py3-none-any.whl`;
- `et_mainsim-0.1.0.tar.gz`;
- `SHA256SUMS`;
- `release-provenance.json`.

The receipt's `primary_artifacts` field contains identities for only the wheel
and sdist. Its non-self-referential `bundle_contract` lists all four uploaded
files and declares that `SHA256SUMS` covers the wheel, sdist, and
`release-provenance.json`; the checksum manifest excludes only itself.
`archive_codec` freezes the sdist as GNU tar inside a fixed-header gzip stream
using DEFLATE stored blocks and freezes the wheel as a ZIP archive using the
stored method. A local pre-tag receipt has `approval.verified=false`; it must
not be treated as required-check evidence.

## Tag and GitHub Release

1. Create the annotated tag `v0.1.0` on the exact reviewed main commit.
2. Push only that tag after independently checking its peeled commit.
3. Dispatch `Release artifacts` from the `v0.1.0` tag. The workflow uses Python
   3.12.13, fetches `origin/main`, requires the tagged commit to be reachable
   from that baseline, and uses only `contents: read` plus `actions: read`.
4. Require `source.tag_object` to identify the immutable annotated-tag object,
   and require its embedded tag name, commit target, and peeled commit to match
   `v0.1.0` and `source.git_commit`.
5. Require `approval.verified=true`. Its repository and commit/main identities
   must match `source`. Each ordered `workflow_jobs` record must come from the
   frozen workflow path on an exact-SHA `push` to `main`, and bind one completed,
   successful workflow run attempt plus the exact completed, successful job
   name, job ID, and URL. Both package-boundary jobs must share the same CI run
   attempt. The builder re-reads GitHub Actions with `GITHUB_TOKEN` and rejects
   missing, duplicate, changed, or ambiguous runs/jobs; a local no-token
   invocation cannot produce a verified tagged receipt.
6. Download the workflow artifact and compare its wheel/sdist `SHA256SUMS` with
   the pre-tag local build. Compare the receipt's release, source commit/tree,
   archive codec, validation, primary artifact identities, and bundle contract;
   the tagged workflow receipt additionally carries tag and approval evidence.
7. Create the GitHub Release from `v0.1.0` and attach the validated wheel,
   sdist, checksum file, and provenance receipt.

Do not publish to PyPI: ET-mainsim's private/direct runtime dependency release
chain is not available there. Do not run a scientific campaign as release
evidence. Galaxy, Aster, varlc, and wdlc science acceptance remains tracked
separately.
